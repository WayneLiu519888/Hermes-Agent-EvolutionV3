# V7.0.9 设计：降频触发 LLM 知识点提取

## 一、方案定位

| 层 | 方式 | 状态 |
|---|------|------|
| D（主） | memory 拦截同步 | V7.0.8 已实现，不动 |
| C（辅） | 每5轮 LLM 提取 | V7.0.9 实现 |
| 旧正则 | _extract_knowledge_snippets | V7.0.9 删除 |

## 二、核心设计

### 2.1 触发机制

```
post_llm_call 每次触发 → 计数器 +1
                       → 缓存本轮"关键信息"（用户消息摘要 + LLM回复摘要）
                       → 计数器 == 5
                         → 组装 prompt，调 LLM API 提取知识点
                         → 写入 memory_entries
                         → 计数器归零，缓存清空
```

### 2.2 缓存策略

只缓存精简摘要，不存完整对话（避免内存膨胀）：

```python
_llm_cache = []  # [{user_msg, llm_reply, ts}]

def _cache_round(user_msg: str, llm_reply: str):
    _llm_cache.append({
        "user": user_msg[:200],     # 用户消息前200字
        "reply": llm_reply[:300],   # LLM 回复前300字
        "ts": datetime.now().isoformat()
    })
```

### 2.3 提取 Prompt

```
你是一个知识提取器。从以下5轮对话中提取3条可复用的知识点。

要求：
- 每条 ≤ 100 字
- 包含足够上下文能被独立理解
- 格式：每条一行，以 " - " 开头
- 不要提取明显临时/对话性质的闲聊

对话记录：
1. 用户: xxx ... | LLM: yyy ...
2. 用户: xxx ... | LLM: yyy ...
...

输出：
 - 知识点1
 - 知识点2
 - 知识点3
```

### 2.4 LLM 调用方式

为避免 hook 递归，不直接调 `chat.completions`，而是用 hermes 的 **auxiliary LLM 快捷接口**：

```python
from hermes_cli.aux import call_aux_llm
result = call_aux_llm(
    provider="auto",    # 用 config 中的默认 provider
    model="auto",
    messages=[{"role": "user", "content": prompt}],
    timeout=30,
)
```

这是 hermes 内置的辅助 LLM 调用，不走 tool loop，不会触发 hook 递归。

### 2.5 质量控制

| 机制 | 说明 |
|------|------|
| 去重 | content_hash SHA256 检查 |
| 最小长度 | 知识点 < 20 字丢弃 |
| 上限守护 | 单次写入 ≤ 3 条 |
| 总数上限 | 复用 V7.0.8 的 10000 上限 |

### 3.2 关键代码

```python
_llm_cache: List[Dict[str, str]] = []
_llm_round_counter: int = 0
_EXTRACT_INTERVAL = 5

def _on_post_llm_call(response, messages=None, model=None, **kwargs):
    """LLM 回复后：关联质量打分 + 缓存对话 + 降频 LLM 提取"""
    try:
        consumer = AssociationConsumer(db_pool)
        text = response if isinstance(response, str) else response.get("content", "")
        if text:
            consumer.score_usage(text)
        consumer.cleanup()

        # 缓存本轮对话
        user_msg = _last_user_message(messages)
        if user_msg and text:
            _cache_round(user_msg, text)
    except Exception as exc:
        logger.debug("post_llm_call hook: %s", exc)


def _cache_round(user_msg: str, llm_reply: str):
    global _llm_round_counter
    _llm_cache.append({
        "user": user_msg[:200],
        "reply": llm_reply[:300],
        "ts": datetime.now().isoformat()
    })
    _llm_round_counter += 1
    if _llm_round_counter >= _EXTRACT_INTERVAL:
        _trigger_extract()


def _trigger_extract():
    global _llm_round_counter
    prompt = _build_extract_prompt(_llm_cache)
    try:
        # 用 hermes 辅助 LLM 调用，不走 tool loop
        from hermes_cli.aux import call_aux_llm
        result = call_aux_llm(
            provider="auto", model="auto",
            messages=[{"role": "user", "content": prompt}],
            timeout=30,
        )
        # 解析并写入 memory_entries
        _store_extracted(result)
    except Exception as e:
        logger.debug("LLM 知识点提取失败: %s", e)
    finally:
        _llm_cache.clear()
        _llm_round_counter = 0
```

## 四、验收

1. 连续 5 轮对话后，memory_entries 中出现自动提取的知识点（content_type="llm_extract"）
2. 知识点长度合理（20-100字），有独立上下文
3. 去重生效（重复内容不重复写入）
4. LLM 提取失败不影响主流程（静默降级）
5. 测试无回归
