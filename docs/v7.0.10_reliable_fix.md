# V7.0.10 调整方案：基于 hermes 实际机制的可靠设计

## 一、放弃的错误设计

| 设计 | 问题 |
|------|------|
| `_engine_instances` 全局缓存 | gateway 多线程/多进程下状态不一致 |
| handler 调 `_get_orchestrator()` → `_get_learning_observer()` | 链条太长，任一环节断裂就全失败 |
| `_init_instance` TTL 重试 | 治标不治本，缓存污染了就不会恢复 |
| `_force_create_*` 暴力绕过 | 太晚介入，handler 根本没被调用 |

## 二、新设计：极简 handler

**核心原则**：每个 handler 独立、自给自足、不依赖任何模块级状态。

```python
def _handle_self_monitor(params, **kwargs):
    """直接创建所需对象，不依赖任何缓存"""
    try:
        from evolution.learning import LearningObserver
        from evolution.db_utils import get_data_dir
        db_base = str(get_data_dir())
        observer = LearningObserver(db_path=f"{db_base}/learning_experiences.db")
        
        health = {
            "success": True,
            "health_score": 70,
            "experiences": len(observer.get_recent_experiences(days=7)),
            "timestamp": datetime.now().isoformat(),
        }
        return json.dumps(health, default=str)
    except Exception as e:
        return json.dumps({"success": False, "error": str(e)})
```

**特点**：
- 每次调用直接 `import` + 创建，不走任何缓存
- 异常直接返回 JSON，不做 fallback 嵌套
- 不依赖 `_get_orchestrator` 等旧函数
- 总共不到 20 行

## 三、同类改造清单

| handler | 改造方式 |
|---------|----------|
| `_handle_self_monitor` | 直接创建 LearningObserver，返回基础健康数据 |
| `_handle_run_cycle` | 直接创建 orchestrator + 所有依赖，每次全新 |
| `_handle_learn` | 直接创建 LearningObserver，写入经验 |
| `_handle_memory_discover` | 直接创建 AssociationDiscoverer（本来就独立） |
| `_handle_audit` | 直接查 SQLite（本来就独立） |
| `_handle_analyze_performance` | 直接创建 analyzer（本来就独立） |
| `_handle_create_tool` | 直接创建 tool registry |

## 四、hermes 配置加固

在 `~/.hermes/config.yaml` 中确保：

```yaml
toolsets:
  - hermes-cli
  - hermes-evolution

plugins:
  enabled:
    - hermes-evolution
```
