# V7.0.9 设计：MemGPT 架构的异步知识整理 Agent

## 一、架构

```
┌─ 主对话（实时）────────────────┐     ┌─ 后台知识 Agent（异步，每5分钟）─────┐
│                                │     │                                     │
│  post_llm_call hook            │     │  hermes cronjob                     │
│    └→ _cache_conversation()    │     │    1. 读未处理的 conversation_cache │
│        写入 conversation_cache │ ──→ │    2. 组装 prompt → 调 LLM         │
│        (摘要，每条≤200字)       │     │    3. 提取 3-5 条知识点            │
│                                │     │    4. 写入 memory_entries           │
│  主对话完全不受影响             │     │    5. 触发 memory_discover 建关联   │
│                                │     │    6. 标记 processed               │
└────────────────────────────────┘     └─────────────────────────────────────┘
```

**核心原则**：主对话不提取任何东西，只缓存。后台 Agent 独立异步工作，用户无感知。

## 二、conversation_cache 表设计

```sql
CREATE TABLE IF NOT EXISTS conversation_cache (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id TEXT,             -- 会话ID（暂无，预留）
    user_msg_hash TEXT NOT NULL, -- 用户消息SHA256[:16]
    user_summary TEXT NOT NULL,  -- 用户消息摘要（≤200字）
    reply_summary TEXT NOT NULL, -- LLM 回复摘要（≤200字）
    keywords TEXT,               -- 关键词（FTS5 匹配用）
    cached_at DATETIME NOT NULL,
    processed INTEGER DEFAULT 0,-- 0=未处理, 1=已处理
    processed_at DATETIME,
    extracted_count INTEGER DEFAULT 0  -- 本批提取的知识点数
);

CREATE INDEX idx_cc_processed ON conversation_cache(processed, cached_at);
CREATE INDEX idx_cc_session ON conversation_cache(session_id, cached_at);
```

**存什么**：只存摘要（≤200字），不存完整对话。200字足够 LLM 理解上下文。

**不存什么**：完整用户消息 / 完整 LLM 回复。隐私 + 存储开销。

```python
def _on_post_llm_call(response, messages=None, model=None, **kwargs):
    """LLM 回复后：质量打分 + 缓存对话摘要"""
    try:
        consumer = AssociationConsumer(db_pool)
        text = response if isinstance(response, str) else response.get("content", "")
        if text:
            consumer.score_usage(text)
        consumer.cleanup()

        # V7.0.9: 缓存对话摘要（不提取，留给后台 Agent）
        user_msg = _last_user_message(messages)
        if user_msg and text:
            _cache_conversation(user_msg, text)
    except Exception as exc:
        logger.debug("post_llm_call hook: %s", exc)
```

### 3.2 `_cache_conversation` 实现

```python
def _cache_conversation(user_msg: str, reply: str) -> None:
    """写入对话摘要到 conversation_cache 表"""
    try:
        from evolution.memory.database import AssociationDatabase
        db = AssociationDatabase(str(get_data_dir() / "associations.db"))

        user_hash = hashlib.sha256(user_msg.encode()).hexdigest()[:16]
        # 去重：同一哈希在5分钟内不重复缓存
        existing = db.connection.execute(
            "SELECT id FROM conversation_cache "
            "WHERE user_msg_hash = ? AND cached_at > ?",
            (user_hash, (datetime.now() - timedelta(minutes=5)).isoformat())
        ).fetchone()
        if existing:
            return

        # 生成摘要（截取前200字）
        user_summary = user_msg[:200].replace("\n", " ")
        reply_summary = reply[:200].replace("\n", " ")

        # 提取关键词（供 FTS5 匹配）
        kw = _auto_tags(user_msg + " " + reply)

        db.connection.execute(
            "INSERT INTO conversation_cache "
            "(user_msg_hash, user_summary, reply_summary, keywords, cached_at) "
            "VALUES (?, ?, ?, ?, ?)",
            (user_hash, user_summary, reply_summary,
             ",".join(kw), datetime.now().isoformat())
        )
        db.connection.commit()

        # 总量控制：保留最近 500 条未处理 + 500 条已处理
        db.connection.execute(
            "DELETE FROM conversation_cache WHERE id IN ("
            "SELECT id FROM conversation_cache ORDER BY cached_at ASC "
            "LIMIT MAX(0, (SELECT COUNT(*) - 1000 FROM conversation_cache)))"
        )
        db.connection.commit()
    except Exception as e:
        logger.debug("对话缓存失败: %s", e)
```

## 四、后台知识整理 Agent

### 4.1 触发方式：hermes cronjob

```bash
# 每 5 分钟触发一次
hermes cronjob create \
  --name "HAE-Knowledge-Agent" \
  --schedule "*/5 * * * *" \
  --skill "hermes-agent-evolution-agent" \
  --prompt "扫描 HAE conversation_cache 表，提取未处理对话的知识点"
```

或者更简单：用 HAE 自己的 `evolution_run_cycle` 在后台定期执行（修改 daemon 逻辑）。

### 4.2 Agent 执行流程（伪代码）

```python
def knowledge_agent_run():
    """后台知识 Agent 主逻辑"""
    
    # 1. 读取未处理的对话缓存（最多20条）
    rows = db.execute(
        "SELECT id, user_summary, reply_summary FROM conversation_cache "
        "WHERE processed = 0 ORDER BY cached_at ASC LIMIT 20"
    ).fetchall()
    
    if not rows:
        return {"status": "idle", "message": "无待处理对话"}
    
    # 2. 组装提取 prompt
    prompt = _build_extract_prompt(rows)
    
    # 3. 调 LLM 提取知识点
    result = call_llm(prompt)
    
    # 4. 解析知识点
    items = _parse_knowledge_items(result)  # 期望 3-5 条
    
    # 5. 写入 memory_entries + 去重
    stored = 0
    for item in items:
        if _is_duplicate(item):
            continue
        write_memory_entry(item, content_type="llm_extract")
        stored += 1
    
    # 6. 标记已处理
    ids = [r["id"] for r in rows]
    db.execute(
        "UPDATE conversation_cache SET processed=1, processed_at=?, extracted_count=? "
        "WHERE id IN ({})".format(",".join("?"*len(ids))),
        [now, stored] + ids
    )
    db.commit()
    
    # 7. 如果新增足够知识点，触发关联发现
    if stored >= 3:
        trigger_memory_discover(max_entries=50)
    
    return {"status": "ok", "extracted": stored, "processed": len(rows)}
```

### 4.4 去重机制

```python
def _is_duplicate(item: str) -> bool:
    ch = hashlib.sha256(item.encode()).hexdigest()[:16]
    return db.execute(
        "SELECT 1 FROM memory_entries WHERE content_hash = ?", (ch,)
    ).fetchone() is not None
```

## 七、验收

1. 对话后 conversation_cache 表中出现摘要记录
2. 手动运行 knowledge_agent → memory_entries 中出现 llm_extract 知识点
3. 知识点质量：有完整上下文、非临时的有价值信息
4. 重复对话内容不产生重复知识点（去重生效）
5. 主对话速度无影响（hook 只做 DB INSERT）
